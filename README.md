# CodeCraftHub

CodeCraftHub is a small Flask REST API demo built as a Coursera lab project for
the course [Generative AI: Elevate your Software Development Career](https://www.coursera.org/learn/generative-ai-elevate-software-development-career/home/welcome).

## Project goals

This project is a hands-on example of applying software development concepts to
a simple course-tracking service. It aims to demonstrate how to:

- Build REST endpoints with Flask.
- Implement create, read, update, and delete (CRUD) operations.
- Validate JSON request data and return useful HTTP errors.
- Persist application data as JSON.
- Generate resource IDs and timestamps on the server.

This is an educational demo, not a production-ready service. It uses a local
JSON file instead of a database and does not include authentication or
multi-user access.

## Features

- Create, list, retrieve, update, and delete courses.
- Update a course's status independently.
- Validate required fields, date format, and allowed status values.
- Automatically create `data/courses.json` when the app starts.

Each course has this shape:

```json
{
  "id": 1,
  "name": "Introduction to Flask",
  "description": "Build a simple web API",
  "target_date": "2026-12-31",
  "status": "Not Started",
  "created_at": "2026-10-22T13:00:00+00:00"
}
```

The `id` and `created_at` values are generated by the API. The required
`target_date` format is `YYYY-MM-DD`. Allowed statuses are `Not Started`,
`In Progress`, and `Completed`.

## Run locally

Python 3.10 or later is recommended.

1. Create and activate a virtual environment:

   ```powershell
   py -m venv .venv
   .\.venv\Scripts\Activate.ps1
   ```

   On macOS or Linux, use:

   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   ```

2. Install the dependencies:

   ```bash
   python -m pip install -r requirements.txt
   ```

3. Start the development server:

   ```bash
   python app.py
   ```

The API is available at `http://127.0.0.1:5000`. The root route (`/`) returns a
welcome message and endpoint overview.

## API endpoints

| Method | Endpoint | Description |
|---|---|---|
| `GET` | `/api/courses` | List all courses |
| `GET` | `/api/courses/<id>` | Retrieve one course |
| `POST` | `/api/courses` | Create a course |
| `PUT` | `/api/courses/<id>` | Replace a course's editable fields |
| `PATCH` | `/api/courses/<id>/status` | Update a course's status |
| `DELETE` | `/api/courses/<id>` | Delete a course |

### Create a course

Send a JSON object containing all required fields:

```json
{
  "name": "Introduction to Flask",
  "description": "Build a simple web API",
  "target_date": "2026-12-31",
  "status": "Not Started"
}
```

For example, with `curl`:

```bash
curl -X POST http://127.0.0.1:5000/api/courses \
  -H "Content-Type: application/json" \
  -d '{"name":"Introduction to Flask","description":"Build a simple web API","target_date":"2026-12-31","status":"Not Started"}'
```

The response has HTTP status `201 Created` and includes the generated `id` and
`created_at` fields. The examples below use course ID `1`; when you create a
course, use the actual ID returned by the API if it is different.

### List courses

```bash
curl http://127.0.0.1:5000/api/courses
```

Returns HTTP `200 OK` and an object containing a `total` count and a `courses`
array. If there are no courses yet, the response is:

```json
{"total": 0, "courses": []}
```

### Get one course

```bash
curl http://127.0.0.1:5000/api/courses/1
```

Returns HTTP `200 OK` and the course object. If that ID does not exist, the API
returns HTTP `404 Not Found` with a JSON error message.

### Update a course

`PUT` replaces the course details. Include all four required fields in the
request body:

```bash
curl -X PUT http://127.0.0.1:5000/api/courses/1 \
  -H "Content-Type: application/json" \
  -d '{"name":"Flask REST API","description":"Build and test an API","target_date":"2027-01-15","status":"In Progress"}'
```

Returns HTTP `200 OK` and the updated course. The API keeps the original `id`
and `created_at`.

### Update course status

The status endpoint accepts only a `status` field:

```bash
curl -X PATCH http://127.0.0.1:5000/api/courses/1/status \
  -H "Content-Type: application/json" \
  -d '{"status":"Completed"}'
```

Returns HTTP `200 OK` and the updated course.

### Delete a course

```bash
curl -X DELETE http://127.0.0.1:5000/api/courses/1
```

Returns HTTP `200 OK` and a confirmation message. Deleting an unknown ID
returns HTTP `404 Not Found`.

### Errors and input rules

- A course requires `name`, `description`, `target_date`, and `status`.
- `target_date` must use the `YYYY-MM-DD` format, for example `2026-12-31`.
- `status` must be `Not Started`, `In Progress`, or `Completed`.
- Invalid or missing request data returns HTTP `400 Bad Request` with a JSON
  `error` message.
- A request for an unknown course returns HTTP `404 Not Found`.
- A course-data file read or write failure returns HTTP `500 Internal Server
  Error`.

These examples use Bash-style line continuation (`\`). In PowerShell, use
`curl.exe` and paste each command on a single line.

## Tests

Automated API tests are in `tests/` and use `pytest` with Flask's test client.
They do not make live HTTP requests or modify the project's course data file;
each test uses temporary storage. The suite covers successful CRUD and status
operations, required-field and input validation, invalid JSON, missing-course
responses, and storage errors.

Install the dependencies if you have not already, then run the tests from the
project root:

```bash
python -m pip install -r requirements.txt
python -m pytest
```

## Troubleshooting

### `python` or `py` is not recognized

Install Python and make sure it is available on your `PATH`. On Windows, try
`py --version`; on macOS/Linux, try `python3 --version`. Reopen the terminal
after installing Python if the command is still not found.

### Flask cannot be imported

Activate the project's virtual environment, then install the dependencies:

```bash
python -m pip install -r requirements.txt
```

If you have multiple Python installations, use the same Python command to
install and run the app (for example, `python -m pip ...` and `python app.py`).

### The server says the port is already in use

Another application may already be using port `5000`. Stop that application,
or change the port in the `app.run(...)` call at the bottom of `app.py`, then
restart the server.

### A request returns `400 Bad Request`

Check that the body is valid JSON, that the `Content-Type` header is
`application/json`, and that all required fields are present. Confirm that
`target_date` is `YYYY-MM-DD` and that `status` is one of the three allowed
values.

### A request returns `404 Not Found`

Check the URL and course ID. The API uses the `/api/courses` prefix, and a
course ID must already exist for GET, PUT, PATCH, or DELETE operations.

### The API returns `500` or course data cannot be read

Check that `data/courses.json` contains valid JSON and that the application has
permission to read and write the `data/` folder. The file should contain a JSON
array, such as `[]` when there are no courses. Back up any data before
manually editing or replacing the file.

## Data storage

Courses are saved in `data/courses.json` relative to `app.py`. This makes the
demo easy to run without a database, but the JSON-file storage is intended for
learning and local use rather than concurrent or production workloads.
